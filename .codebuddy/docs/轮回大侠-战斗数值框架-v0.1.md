# 《轮回大侠》战斗数值框架 v0.1

> 地位：**一切数值的唯一出处**。武学卡、侠客、境界、天赋树的数值都必须能回溯到本文档的公式；本文档没定义的数值不进游戏。
> 数值三分类：有 rationale（写了为什么）/ [PLACEHOLDER]（拍脑袋起点，附验证路径）/ 待验证（要 M0 模拟或 playtest 确认）。

## 1. 单位属性模型

每个战斗单位（侠客/敌人/召唤物）有 5 个基础属性：

| 属性 | 符号 | 说明 |
|------|------|------|
| 气血 | HP | 归零即败 |
| 攻击 | ATK | 一切伤害的基数 |
| 防御 | DEF | 减免受伤；三种伤害类型口径不同（外功硬减/内功比例化解/真伤无视），见 §2。**标准轴 30**（2026-10-15：100 → 60 → 50 → **30**，每级 **+2**，**不乘定位系数**；见 §2 Kd 口径与 §11） |
| 速度 | SPD | ATB 条充能速率，充满需 `100/SPD` 秒 |
| 受击权重 | W | 普攻索敌的抽样权重，**基础值 10**（1 号位 ×3 = 30），见 §7 |

**派生**：`普攻 DPS = ATK × SPD / 100`。rationale：这个公式让 ATK 和 SPD 在纸面上完全对称（乘积关系），但 SPD 还驱动行动类武学触发频率——**速度双吃是刻意的**，它给构筑一个"堆速度"的明确路线，验证路径：M0 模拟若速度 100% 独大（GDD 失败信号 D），给行动类武学加触发间隔下限。

**有防御，但只对外功生效（2026-10-15 修订，推翻早期"不做防御"）**。rationale：伤害分**外功/内功**两条公式——外功吃防御减免（减法曲线，收益递减、不免疫），内功按比例化解、**永不免疫**（见 §2）。这给构筑两条明确的进攻路线（大倍率硬吃防御 vs 小倍率比例穿透），同时把"防御"这条曲线的爆炸半径限制在一条伤害线上——敌方强度仍主要靠 HP 曲线表达，DEF 只做次要调参。

## 2. 伤害公式

```
基础伤害 = 攻击方ATK × 武学倍率 × 武学乘区 × 境界乘区 × 装备乘区 × 根骨乘区 × 图鉴乘区

外功（硬减）    ：实际 = max(基础 × 15%, 基础 − DEF)
内功（比例化解） ：实际 = max(基础 × 25%, 基础 × Kd / (Kd + DEF))      Kd = 100
真伤（无视减伤） ：实际 = 基础
```

> **Kd 与 DEF 基准的标定口径（2026-10-15 多次修正，v4.4 定案）**
> 1. **Kd = 100（2026-10-15 由用户直接指定）**。既有规则是"**Kd ≈ 标准单次伤害**"——ATK 基准提到 60 后，标准普攻 = `ATK 60 × AtkScale 1 = **60**`（2026-10-16 三只全局 Scale 归 1，见表注）；本次用户明确取 **100**，即内功**比该规则更强一档**（Kd 越小、化解越高）。更早的原值 400 远大于单次伤害量级，内功减伤只剩 ~6%、全面优于外功，两条公式的"分流"设计**形同失效**——那是公式层面的错误，不是调参问题。
> 2. **DEF 标准轴 100 → 60 → 50 → 30（v4.2）；每级成长 0.6 → 2（v4.4）；且 v4.3 起 DEF 不再乘定位系数**（口径演进："基础防御降低一点，成长加一点" → "基础防御30±40%" → "谁要你设定的定位系数了?"）。**去掉定位系数后全池 DEF 收进 19 ~ 42**（L1，中心 30，即 30±40%），均值 L1 28.8 → L40 **105.3（×3.66）**。
> 3. 两条曲线的**交叉点：`基础 = Kd + DEF`** —— 低伤吃内功（比例化解）、高伤吃外功（硬减）。下表为引擎实测（`DealDamage` 直调，非纸面推算）：
>
> | 侠客（L1 DEF / L40 DEF） | 外功 @60 | 内功 @60 | 外功 @30（低倍率卡） | 外功 @270（高倍率卡） | L40 外功 @255 |
> |---|---|---|---|---|---|
> | 莫问剑（10.6 / 28.9） | 17.7% | 9.6% | 35.3% | 3.9% | 11.3% |
> | 铁震山（8.2 / 28.9） | 13.6% | 7.6% | 27.3% | 3.0% | 11.3% |
> | 石敢当（6.0 / 30.6） | 10.1% | 5.7% | 20.2% | 2.2% | 12.0% |
> | 沈孤鸿（6.1 / 21.3） | 10.1% | 5.7% | 20.2% | 2.2% | 8.3% |
> | 扫地僧（4.7 / 25.0） | 7.9% | 4.5% | 15.7% | 1.7% | 9.8% |
>
> （DEF 刻度 = HeroConfig `BaseDEF` —— **2026-10-16 起换算已折进内容表，`DefScale = 1`，表值即战斗值**；内功减伤率恒为 `DEF/(DEF+Kd)`，与伤害量级无关。**60 = 标准单次普攻** = ATK 60 × AtkScale 1；L40 标准单次 = 255）
>
> ⚠️ **@60 是"标准单次伤害"基准，不是实战伤害**。L40 实战单次伤害可达 ~255（ATK 255 × AtkScale 1），此时全池最高的 DEF 30.6 也只减 ~12%——**DEF 仍是随等级"相对贬值"的属性**（满级倍率 HP ×4.9 / ATK ×4.25 / DEF ×3.66）。v4.1~v4.4 把它从"基础厚、几乎不涨"改成"基础薄、涨得快"，方向是**前中期节奏变快、后期略微回肉**，没有、也不打算反转这条趋势。
>
> **读表要点**：外功是**绝对值减法**，所以 DEF 最高的人对低倍率卡有明显压制（15.9% @66）而对高倍率几乎无感（1.8% @594）——这正是"外功靠倍率堆量"的量化形态；内功是**固定比例**，对所有量级一视同仁（@60 档 6.7%）。**交叉点 `基础 = Kd + DEF`，换算成卡面倍率：L1 阈值 ≈ 1.79、L40 ≈ 0.50**（倍率低于阈值时内功更优）——即**小额/高频卡用内功、大倍率爆发卡用外功**；这条分界线随等级**左移**（后期内功的优势区间收窄，因为伤害涨得比 DEF 快）。

> **伤害类型是武学卡面字段**（`DamageType`），**三种减免口径**（2026-10-15 定稿）：
> - **外功**（招式/兵器）：**减法硬减**。对小伤害惩罚重、对大伤害更划算——高倍率爆发卡走外功；面对高防目标会"打不动"（框架 §10 第 5 条卡关形态是打不动，不是被秒），15% 下限防免疫。
> - **内功**（内力/毒/法诀）：**比例化解**（收益递减、永不免疫）。对小伤害更划算、与攻防绝对值无关只与比例有关——高频/多段/DoT 卡走内功。
> - **真伤**（无视减伤）：**稀缺类型**，用于克制高防 Boss 与"自损/同归"类卡（七伤拳、天地同寿）。不吃 DEF 减免（护盾仍正常吸收）。
>
> 设计意图：**外功靠倍率堆量、内功靠频率摊薄**——两者在同一根防御轴上互补（减法偏爱大伤害、比例偏爱小伤害，存在交叉点），真伤作为破局的稀缺资源。三个系数的卡面归属以配置表 `DamageType` 为准（当前口径：相性属 毒/奇门 或含 DoT 的伤害卡 = 内功；**破招/破防类（独孤九剑）、自损/同归类（七伤拳、天地同寿）= 真伤**；其余伤害卡 = 外功。全库 65 张中真伤仅 3 张）。

- **武学倍率**：单张武学卡面上的乘数（普攻 = 1.0）。
- **五乘区**各自独立累乘（rationale：乘算而非加算是滚雪球的发动机——每开一个新乘区，旧乘区的积累不被稀释，膨胀感来源；若改加算，后期所有新系统都会变成"提升 2%"的笑话）。
- 每个乘区内部多个加成项**加算后作为该乘区的值**（如根骨乘区 = 1 + Σ根骨节点加成），乘区之间乘算。rationale：同一乘区内加算防单乘区失控，乘区间乘算保膨胀。

### 2.1 治疗 / 护盾（与伤害共用"卡面 × 攻击"口径）

治疗与护盾**不是**另一套数值体系 —— 它们与伤害共用"卡面 × 基准"的解析口径，区别只在**基准来源**：

| 卡面 `CalcBase` | 实际结算值 | 何时取值 |
|---|---|---|
| **ATK 倍数** | `施法者攻击 × 卡面倍率` | **结算时实时**（吃等级、攻击增益、召唤者属性） |
| **气血%** | `施法者最大气血 × 卡面百分比` | **装配时折算成绝对量** |
| **固定值** | 卡面值 | 装配时 |

> ⚠️ **2026-10-16 修：治疗/护盾曾漏乘攻击（表现即"全队护盾 1"）**
> **现象**：开局铁震山自带「金钟罩」（`CalcBase = ATK 倍数`、`CalcValue = 122`、目标**全体**），实战却只给出 **1.22 点**护盾 —— 界面上就是 **"🛡 护盾 1"**。
> **根因**：`BattleSkill.Mult` 一个字段承载了**两种语义**（倍数 / 绝对量），而引擎**只有伤害**分支乘了攻击（`u.EffAtk(T) * s.Mult`），治疗与护盾直接 `+= s.Mult`。于是所有"×攻击"型治疗/护盾都退化成"给出 1.22 的绝对值"，**等于完全失效**。
> **修法**：`BattleSkill` 新增 **`MultOnAtk`** 标记 Mult 的基准（伤害恒 `true`；治疗/护盾按卡面 `CalcBase` 判定），引擎统一走 `AmountOf(u, s) = MultOnAtk ? 施法者攻击 × Mult : Mult` —— 以后**不可能再漏乘**。
> **影响面**：全表治疗/护盾共 7 张，其中 **2 张是 ATK 倍数型**（Id5 回风拂柳·治疗、**Id6 金钟罩·护盾·全体**），另外 5 张是气血%型（不受影响）。

**修好之后，僵局反而缓解了 —— 这是个反直觉但重要的结论。** 四组对照（开局队镜像、含武学、各 300 场）：

| 对照 | 中位时长 | 超时% | 护盾/场 |
|---|---|---|---|
| 旧行为（两张都按绝对量） | 120.0s | **90.7%** | 18,704 |
| **只修金钟罩** | 112.0s | **43.0%** | 30,214 |
| 只修回风拂柳 | 120.0s | 85.3% | 19,346 |
| **两张都修（当前）** | 109.1s | **35.3%** | 30,485 |

**机制**：旧行为下**只有 1 号位（铁震山，自带铁布衫·气血%护盾）撑得住**，脆皮与输出位开场就死 → 战场退化成 **"两个铁震山互掐"**；而铁震山的护盾供给（铁布衫 159 / 受击 2 次 ≈ **79.5/击**）**高于他自己的普攻**（66 攻 − 8.2 DEF ≈ **57.8/击**）→ **双方都打不死 → 永久僵局**。金钟罩是**全体护盾**，修好后输出位存活、持续输出打穿这道平衡 → 超时率腰斩再腰斩。

**结论：八成超时不是"护盾/治疗太强"，而是"输出位死得太快、战场退化成双坦互掐"。** 此前"削续命"的调参方向因此被证伪 —— 真正该管的是**后排（输出位）在 1 号位承伤机制下的生存**：1 号位权重 30、其余 10，但后排血量只有 1 号位的 1/3 上下，**按权重平摊伤害时后排先倒**。

> 📌 **仍存在的同类隐患（待处理）**：`Poison` / `Burn`（叠毒 / 灼烧）的**伤害用的是引擎全局系数**（`PoisonPerStack` / `BurnRate`），**技能自带的 `CalcValue` 没有接进引擎**。两处默认值恰好等于卡面值（火焰刀 15%），所以现在看不出差异 —— 但一旦卡面改动就会静默失效，与本次修掉的是同一类病。

## 3. 敌方成长曲线（滚雪球主体）

层数 `n`（n = 1, 2, 3, ...）：

```
敌方属性(n, 模板) = Base(模板) × Rate(模板)^(n−1)      n = 层数（1, 2, 3, …）

模板六字段（EnemyConfig.xlsx）：BaseHp / BaseAtk / BaseDef（第 1 层基础）
                              HpRate / AtkRate / DefRate（每层成长倍率）
标准杂兵基准：Base 174 / 26.9 / 16.5        Rate 1.16 / 1.12 / 1.10
            （= 旧式 `150×1.16^n / 24×1.12^n / 15×1.10^n` 在 n=1 处取值的等价改写）
精英 = 同档杂兵 × 2.0 HP / × 1.3 ATK / × 1.3 DEF    层主 = × 8 / × 1.5 / × 1.3
```

rationale：`a > b > c` 刻意为之——**HP 涨最快（血量是难度主体）、ATK 次之（生存压力）、DEF 最慢（只需让"高防"成为阶段特征，不能变成随时打不动的墙）**。若 c 接近或超过 b，会出现"层数越高越打不动"的全面堵死，而 GDD 想要的卡关是"某几层打不动、换构筑能过"。敌方 `BaseDef` 的标定见下条验证路径（v5.0 起敌方属性已**表化自持**，`DEF0` 常数退役；换算已折进表，`DefScale = 1`）。

rationale：`a > b` 刻意为之——生存压力增长快于输出压力，卡关的形态是"打不动"而不是"被秒杀"；被秒杀的挫败感远强于打不动。基准值 HP0/ATK0 由首层体验反推：首层小怪应在 2~3 次普攻内死亡 [PLACEHOLDER：HP0 = 开局侠客 ATK × 2.5]。

验证路径：M0 模拟后确认单场时长中位数落 10~30s；落不进 → 只调 a 与 HP0，不动曲线形状。

> 2. **血量跨波延续**：引擎 `BattleUnit` 新增 **`StartHp`**（`Clone()` 原本**无条件满血起手**，这是本次唯一需要动的引擎点位）。波与波之间：**存活者回补 10% 最大气血**、**阵亡者保持阵亡**（口径）；**跨层整队重建**（满血、阵亡者归队）[假设] —— 否则长跑下来必然只剩 1 人，无法继续。
> 3. **普通敌人基础 +10%**（`EnemyConfig` 的**小怪**三项 ×1.10；精英/层主不动）：v5.2 起普通波是纯小怪（不再带精英），单波强度比 v5.0 的"1 精英 + 3 小怪"低，这 +10% 是补偿性上调；**真正的强度来源是"波数"**。
>
> ⚠️ **经济侧连带影响**：掉落挂在**每个击杀**上（§4），一层由 4 杀变成 **24~36 杀** → **整层掉落放大约 6×**（层 10 整层修为由 `8.8 × 1.16^层` 涨到 `52.9 × 1.16^层`）。**per-kill 单价未动** —— 口径只要求加波、没要求降价。挂机模拟（5 种子 × 6000 波）：200 波到层 15~16·总等级 72~80、1000 波到层 19~20·总等级 132~136、3000+ 波总等级触顶 160（L40 满）。**层 20 仍是等级绝对墙**（结构性，见 GDD 决策 20）。

> | 单位 | 武学来源 | 数量 |

> | **小怪** | 从【已实装全池（49 张）】按层随机抽，受**品阶上限**约束 | `SkillCount + (层−1)/10` → 1/2/3/4/5… |
> | **精英 / 层主** | **固定技能组**（`EnemyConfig.Skills` 列写死武学 Id） | 精英 2~3 张、层主 3 张，**不随层变化、不受品阶限制** |

>
> **抽卡是确定性的**（按 `(层, 槽位)` 的整数哈希取不重复索引），同一层永远同一套，便于复现与对比调参。

## 4. 修为产出与消费（此生经济）

```
修为产出(n) = c × a^n       c [PLACEHOLDER：使首层击杀给 5~10 修为]
```

- 产出指数与敌方 HP 同底数 `a`——rationale：**推一层的修为跳档和怪物变强同步**，玩家感知是"越打越富"，卡关感由消费侧制造。
- 消费侧（升级/强化）费用增长 = `d^k`（k 为该线已购买次数），**d 略大于 a**（d = 1.18 [PLACEHOLDER]）。rationale：消费增长略快于产出 → 同层刷怪的收益随次数递减 → 逼玩家推层；推不动时攒一攒又能推——这是放置增量"卡-攒-破"心跳的数学来源。

> **M2.2 落地与标定（2026-10-15，v3 击杀即时制）**：敌方每击杀一个单位就立刻掉两样（口径："击杀就可立即获得经验资源" + "敌方掉落的是修为(就是经验)和银两"）——
>
> | 掉落 | 公式（**每个击杀**） | 去向 |
> |---|---|---|
> | **修为（= 经验）** | `0.5 × 1.16^层`（每人一份） | 即时累进每侠客的修为池；**升级在本场结束时统一结算** |
> | **银两** | `2.5 × 1.16^层`（整队一份） | 即时进货币账户；sink = 客栈招募 / 武学商店 / 装备强化 / 境界突破 |
>
> - v5.1 时一层 4 个敌人 → 每人合计 `2.0 × 1.16^层`、银两合计 `10 × 1.16^层`；**v5.2 起一层 = 6~9 波 × 4 人 = 24~36 杀**（层 1 为 6 波 24 杀 → 每人合计 `12 × 1.16^层`），**整层掉落随之放大约 6×** —— 这是"层内多波"的连带影响，**per-kill 单价未动**
> - **为什么升级要等战斗结束**（用户口径）：战斗中途改等级会让本场已建好的单位与新等级脱节 → 属性混乱。故"记经验"（击杀时）与"升级"（战斗结束时）**必须分成两步**
> - **即时制下没有"败北折扣"**：打不动就杀不掉，收入自然变少 —— 比原来"固定给 50%"更精确
> - 升级成本 `LevelCost(L) = 30 × 1.18^(L−1)`，上限 L40（框架 §11）；`LevelD(1.18) > GainA(1.16)`（§4 规定）
>
> **推图规则（2026-10-15 用户口径："推图失败返回上一层重复刷图"）**：
>
> ```
> 推图模式（默认）：胜 → 进下一层；负/平 → 退回上一层 且 转入挂机模式
> 挂机模式：      停在该层重复刷（胜也不再进层），每刷 StageConfig.RetryEvery (=10) 场
>                自动重试上面那层一次；玩家点「继续推图」可随时结束挂机往上冲
> ```
>
> 语义：**打不过就退到打得过的层刷，攒够了再冲** —— 这正是放置游戏"卡-攒-破"的循环体。
> ⚠️ **自动重试（每 10 场一次）是我的补充**（[假设]）—— 用户只说了"重复刷"，但纯手动会让挂机期"等级涨、层数冻死"；把 `RetryEvery` 置 0 即可退回纯手动。
>
> **掉落 vs 升级成本**：
>
> | 层 | 每杀修为 | 每杀银两 | 整层(4杀)修为 | 升到该级累计修为 | 等效击杀数 |
> |---|---|---|---|---|---|
> | 1 | 0.58 | 2.90 | 2.3 | 30 | 52 |
> | 10 | 2.21 | 11.03 | 8.8 | 706 | 320 |
> | 20 | 9.73 | 48.65 | 38.9 | 4399 | 452 |
> | 30 | 42.92 | 214.62 | 171.7 | 23728 | 553 |
>
> 成本累计（≈`1.18^L`）**始终快于**掉落（`1.16^层`）→ "同层刷怪越刷越慢"成立 ✓（§4 的设计意图）
>
> **挂机模拟（失败退层 + 每 10 场自动重试 + 击杀即时掉落；5 种子 × 2000 场，零操作）**：
>
> | 场次 | 100 | 500 | 1000 | 2000 |
> |---|---|---|---|---|
> | 到达层数 | **14~15** | **17~20** | **19** | **19** |
> | 全队总等级 | 52~56 | 104~108 | 132 | 148 |
>
> - **零操作下能从卡关层 10 一路推到层 19** ✓ 且**层数随等级上涨**（v2 的"挂机永不重试 → 层数冻死"问题已修）
> - ⚠️ **层 19~20 仍是绝对墙**：总等级 132 → 148 而层数不动。根因**结构性**：等级上限 40 只给 ×4.9 属性，推图曲线 20 层却 ×19.5；`log(4.9)/log(1.16) ≈ 10.6`，正好 10 → 19。**这是五乘区分工**（GDD §5），推图深度靠武学/境界/装备 —— 留给 M2.4/M2.5


## 5. 大劫 Boss 曲线（转世发动机）

```
大劫Boss强度(k) = 当前层主强度 × m^k     k = 已转世次数, m = 1.8 [PLACEHOLDER]
```

- 强度同时作用于 HP 与 ATK。
- 胜负不设剧本：玩家 DPS 成长线 vs 这条指数线，交叉点自然出现。rationale 见 GDD §3.1。
- 验证路径：用 M0 内核模拟"无干预普通玩家"成长线，目标首次大劫（2~4h）可胜、第 3~5 次大劫自然败北；偏离则只调 m。

## 6. 道行公式

```
道行 = floor( (此生最高层数)^0.5 )     胜利大劫 ×1.5 [PLACEHOLDER]
```

- 层数 100 → 10 点；层数 400 → 20 点。**道行翻倍需要 4 倍层数**——亚线性的体感就是这句话。
- rationale：转世收益递减保证"转世→更快回来→再推一步→再转世"的心跳；若线性，最优策略变成永远不转世，循环断裂。

## 7. 概率仇恨参数

**受击权重采用 10 基准**（2026-10-15 修订：原 1.0 基准整体 ×10——纯单位换算，比例与平衡不变，只为让修正量落在整数刻度上）：

| 位置 | 基础权重 | 血量加成 |
|------|----------|----------|
| 1 号位 | 30（=10 ×3 系数） | +30% [PLACEHOLDER] |
| 2~4 号位 | 10 | 无 |
| 召唤物 | 15（=10 ×1.5） | 由召唤武学定义 |

- 权重 [30,10,10,10] → 1 号位理论承伤占比 50%（验收区间 45%~60%）。
- 权重修正（嘲讽/隐身）为**加减法**叠在基础权重上，**下限 1.0**（=原 0.1 的 ×10；不能归零隐身）。rationale：乘法修正会让权重流指数失控；加法修正有界，"嘲讽坦"和"隐身刺"是两条有上限的路线。嘲讽幅度基准：**狮子吼 W+12**（=原 +1.2 的 ×10）[M0 实测：原 W+2 导致高速度坦承伤 80%+ 死局，砍至 +1.2 后回落 65~70%]。其余权重卡：金刚怒目 +20、凌波微步 −5、神行百变 −10、太极推手 ±10。
- **召唤物群体减伤（2026-10-15）**：召唤物受到 `Tgt=全体`（群体）伤害时**减伤 50%**——AoE 仍是召唤克星（一发打一片），但**不再一发清场**。实测依据：修前最强 AoE 475 一击秒杀 272 HP 的灵蛇，召唤物阵亡中 20.4% 属"同刻 ≥2 个一起死"的团灭特征；修后无单体被一发带走。
- **召唤物类型分档（2026-10-16，新增第 4 张内容表 `SummonConfig`）**：口径"召唤物类型分档，召唤物的血攻和武侠相关，限 1 的血攻多点"。**血攻随召唤者** —— `气血 = 召唤者最大气血 × HpRatio`、`攻击 = 召唤者攻击 × AtkRatio`（召唤物强度自动跟随召唤者的等级/装备，**不需要单独的成长曲线**）；`速度 = max(SpdFloor, 召唤者速度 × SpdRatio)`。**类型档位**：

| 类型 | 召唤物 | HP× | **固定血** | **每次受击** | ATK× | 权重 | Ttl | **同时上限** | 定位 |
|---|---|---|---|---|---|---|---|---|---|
| `tank` | 刀盾傀儡 | **0.80** | — | — | 0.45 | 20 | 20s | **1** | 肉盾：唯一一只，给厚血，**靠血活着** |
| `dps` | 灵蛇 | 0.25 | — | — | 0.60 | 10 | 20s | **2** | 输出：咬得凶但脆，随召唤者加速（1.2×） |
| `sub` | 纸人 | 0.17 | — | — | 0.08 | 25 | 20s | **3** | 替死：薄壳虫群，**靠权重把伤害吸过来再死掉** |
| `sword` | 飞剑 | **0（不用比例血）** | **2** | **−1** | 0.80 | 10 | 20s | **2** | **2 层计数体**：免疫大伤害秒杀、怕高频多次命中；最快（1.5×召唤者速度） |

**分档原则三条**：① **总量守恒** —— 单张召唤卡的总血量控制在召唤者的 **0.40 ~ 0.80**（上限越高，单体越薄）；② **限 1 的补更多**（用户口径）—— `tank` 单体 **0.40/0.30 → 0.80/0.45**（血 ×2、攻 ×1.5），只有一只时它得对得起那个位置；③ **权重与血量分工** —— `tank`（W20 / 血 0.80）靠血厚活，`sub`（W25 / 血 0.17）靠权重把伤害吸过来然后死掉，是**替死**不是**肉盾**。

**上限三层**（由内到外）：① 武学覆盖 `SkillConfig.SummonMax`（**0 = 跟随类型**；当前只有**万剑归宗 = 1** 是专属收紧，其余 5 张召唤卡全为 0）；② **类型档位** `SummonConfig.SummonMax`；③ 全队 `BattleConfig.SummonCap` —— **2026-10-16 v5.7 由 4 提高到 8**（口径"全队召唤上限提高"；理由：4 侠客 × 2 = 8，让"每人带一张以上召唤卡"的召唤流真能同时铺开，同时它仍是**外层闸**，单卡上限由类型档位管住）。前两层解决的是同一个病：上限原先只挂"全队"且先到先得，**触发最快的召唤卡会独占全部召唤位**，其余召唤卡形同不存在。探针实测（每张卡每次行动必触发的极限场景）：类型档位各自生效 **tank 1 / dps 2 / sub 3 / sword 2**；组合 双卡 `tank+dps` → 3、双卡 `sub+sub` → **6**（3+3，v5.6 时被全队 4 兜住，现在放开了）、三卡 `tank+dps+sub` → **6**（1+2+3）；武学覆盖 `tank`=3 → 3、`dps`=1 → 1；**类型上限置 0 → 8**（回退到全队）、**六卡齐上（类型上限合计 12）→ 8**（外层闸确实放到 8）。
- **飞剑 = "命中计数体"（2026-10-16，`SummonConfig` 新增 `FixedHp` / `DmgPerHit` 两列）**：口径"**飞剑血量固定为 2，每次受击 -1**"。`FixedHp > 0` 时气血用**固定值** —— 既不乘召唤者、也**不吃全局 `HpScale`**（它是"层数"不是血池）；`DmgPerHit > 0` 时**无视伤害量**，一次命中只扣这么多。于是飞剑从"玻璃炮"变成**2 层计数体**：**免疫一发大伤害秒杀**，但被**高频多次命中**（AoE / 连击 / 多段）克制得极狠 —— 这是它与普通"脆皮"的分界：**脆皮死于伤害量，飞剑死于命中次数**。探针实测：召唤者 HP 200 / 1000 / 20000 → 飞剑 HP **恒为 2**；敌人 ATK 1 / 132 / 1,000,000 → 全部**恰好 2 次命中必死**。
- **一次召唤多只（2026-10-16，新增列 `SkillConfig.SummonCount`）**：口径"**御剑术是召唤 2 飞剑（不是上限）**"。`SummonCount` = **每次触发召唤几只**（1 = 单只），与 `SummonMax`（**同时存活上限**）是两件事；多只召唤**逐只走同一套上限检查**，超限即停。御剑术因此设为 `SummonCount = 2 / SummonMax = 0`（跟随剑类档位 2）——**一次召 2 把**，能不能留住交给类型档位与全队上限。探针实测：御剑术单卡首次触发后在场 **2 把**、跑满 180s 峰值 2 把；万剑归宗单卡 **1 把**；两卡齐上峰值 **3 把**（2 + 1，全队上限 4）。
- **同类召唤物堆叠显示（2026-10-16 v5.7，表现层）**：口径"同一召唤物显示上可堆叠"。表现层把**同阵营 + 同名字**的召唤物合并成一张**堆叠卡**，显示 `名字 ×N`、**聚合血条**（Σ当前 / Σ上限）、以及**最快到期的剩余时间**。这条与"全队上限提高到 8"是**配套**的 —— 一单位一卡的旧布局在 8 个召唤物时会把战场塞爆并超出屏幕高度。可行性来自一个结构事实：**召唤类型只有 4 种**（tank/dps/sub/sword），所以**每侧最多 4 张堆叠卡**，放在中路两侧（不占侠客卡列），4 × 62px 稳定落在 720p 高度内。
- **召唤物死亡不留"尸体"（2026-10-16）**：召唤物阵亡（含 TTL 到期）后**从队伍列表里真正移除**，不再以"`Hp = 0` 的占位单位"留在战场。rationale：索敌 / 治疗 / 上限计数虽都已过滤 `Alive`，但尸体仍会 —— UI 卡片不消失、召唤卡的行位计算把它算进去、每帧还要白跑一次 `TickUnit`。实现为**延迟移除**（`_pendingRemove` 登记 + 在 `Run`/`Step`/`Advance` 的**非遍历点** flush），否则会踩"集合已修改"。**侠客阵亡仍保留尸体**（同一场内不复活，需要它占位判胜负）。实测：真实推图 60 场、80 次召唤物阵亡，**战斗结束后残留尸体 0**。
- **召唤号令齐射（2026-10-16，新增列 `SkillConfig.SummonOrder`）**：`SummonOrder = True` 的召唤卡，在**召唤之后**命令己方所有**同类型**且存活的召唤物各立即普攻一次。语义是"**命令**"而非"额外行动" —— 不走 `Act()`，不增加行动计数、不触发召唤物自身的武学，只结算一次普攻并抛伤害事件（UI 能看到齐射）；"同类型" = `SummonSpec.Kind` 相同。当前只有 **万剑归宗**（"召唤 1 飞剑，并号令己方全部飞剑齐射"）：它自己只留 1 把，但每次触发让全队飞剑（含御剑术养的那 2 把）一起打一轮 —— 定位从"召唤卡"变成"**剑阵指挥卡**"。探针实测（强制每回合触发、180s）：号令 **66 次**，**每次打出的攻击次数 == 场上飞剑数（66/66 精确匹配）**，峰值 3 剑（御剑术 2 + 万剑归宗 1）；180s 内召唤物总伤害 只有御剑术 28,476 → 御剑术+万剑归宗 **74,569**（+46,093）。

## 9. 触发式武学的触发语义（已定稿，供实现照抄）

1. 每次行动默认放普攻（倍率 1.0，按权重随机索敌）。
2. 行动类武学触发时**默认与普攻同放**；标注"不能普攻"者替换该次普攻。
3. 受击类武学在被击结算后立即触发，不占行动。
4. 血量阈值类武学每场战斗每单位只触发一次（首次跌破阈值）。
5. 同一单位同一次事件触发多张武学时，按装配槽位顺序依次结算。
6. 受击触发链最大深度 8 层（防 A 打 B、B 反 A、A 再反的无限递归）。[PLACEHOLDER · M0 压测]
7. **连击条件（v0.5.2 修订，替代旧"额外行动"版）**：连击 = 触发条件——当前单位行动时，若**上一个行动的单位为友方**（含召唤物；含自身因速度差连续行动的极端情况），连击条件成立。连击可与次数/概率条件组合（如"连击时25%"），命中后按正常行动时武学管线结算（同放/不能普攻规则照常）。不产出额外行动，无链式风险。rationale：连击把"行动序列"变成构筑资源——敌方行动断链，**速度同步**（全队速度接近且快于敌方）是覆盖率核心杠杆，召唤物可续链。**M0 实测修正**：覆盖率是敌我速度比的函数，同步构筑实测 94.9%（非 30~60% 常数）——高覆盖率是同步流的构筑回报，代价由 ATK 预算支付（SPD 为基准 1.6 倍时 ATK 约需打 6 折）。速度同步流为 M0 全局无败局构筑，平衡杠杆（连击冷却/闪避-权重联动/疲劳曲线差异化）见 M0 报告 §3.3，M2 逐项验证。
8. **闪避语义（v0.6 新增）**：闪避 = 在伤害结算前判定，成功则该次攻击完全落空（不掉血、不掉盾、受击计数不+1、不触发该单位的受击类与血量阈值武学）。同一单位多来源闪避概率**加算，上限 50%** [PLACEHOLDER · 等效血量最多 ×2]；攻击方行动照常消耗。rationale：闪避与反伤在单次受击上互斥（闪避了就没有反伤），两条坦度路线天然分流；闪避不降受击权重——闪避坦仍吸仇恨但白嫖伤害，与权重系统正交。
9. **召唤物规则（v0.7 新增，2026-10-15 修正）**：召唤物存在 20s、只会普攻、占受击权重池（W=15/10 基准）、上限 4 个；HP/ATK 为召唤者的比例（坦克 40%/30%、输出 25%/60%、替死 25%/10%、飞剑 20%/80%），SPD 固定 60（飞剑 ×1.5）。**受群体伤害（Tgt=全体）减伤 50%**——召唤物是"吸收单体火力的盾"，但吃群体是明确弱点；减伤保证弱点"疼但不秒"，避免一发 AoE 清场（rationale：召唤物是消耗品，应死于持续输出与 20s 到期的自然规律，而非单体被一发带走）。

**效果词汇表（v0.2 随武学清单扩充）**：伤害 / 治疗 / 护盾 / 召唤 / 权重修正（已定稿）；吸血 / 叠毒·灼烧（DoT 不吃武学倍率，只吃乘区）/ 成长（当局叠乘，超时封顶）/ 沉默（对 Boss 减半）/ 护盾转伤害 / 复制（不可套娃）（[扩展·待确认]，约束细则见武学清单 v0.5"新增效果词汇"表）。注：连击已移出效果词，改为触发条件（见本节第 7 条）。

**污染语义（v0.5 新增）**：
1. 污染 = 将目标武学的**卡面**临时替换为指定卡面（当前为【野球拳·染】），普通怪整场生效，Boss 限 15s [PLACEHOLDER]。
2. 替换时该武学计数器清零重计；**参数修正挂在槽位上而非卡面上**——套装/词条对槽位的修正继续作用于新卡面（rationale：否则污染会连带清除玩家装备收益，产生"我治我自己"的负反馈）。
3. 已污染的卡不可再被污染（防连锁覆盖与优先级争议）。
4. 污染效果**免疫复制**（左右互搏等复制词对污染不生效）。
5. 污染对敌我双方的结算规则完全一致（对称设计）——玩家能用的，AI 后期也能用，设计敌方构筑池时预留反制（如高抗性 Boss）。

**重放语义（v0.3 新增）**：
1. 武学可带 `重放概率 p` 与 `重放上限 C` 字段。**全局基线：所有触发型武学自带 p=1%、C=2**（总命中上限2，期望 1.01——彩蛋层，让重放修正词对全卡池有意义）；卡面显式写了重放字段的（如重放型 4 张）以卡面值替代基线。开战光环类不适用（非触发型释放）。
2. 武学触发释放后，立即按 p 判定：成功则**同一效果再放一次**，再次判定……直到判定失败或达到 C 次（C 为**总命中次数上限**）。
2.5 叠加规则：最终 p = 基线或卡面值 + 套装修正 + 词条修正（**词条对 p 的合计加成 ≤ +10%**，防随机词条喧宾夺主；总上限 90%）；最终 C = 基线或卡面值 + 修正（上限 25）。
3. 重放链是几何分布：期望命中 `E = (1−p^C)/(1−p)`。数值定档表（设计依据，M0 验证）：p=70% → E≈3.3；p=85% → E≈6.6。rationale：重放的价值是长尾方差（"偶尔十八连"），p<50% 时长尾不存在，上限 C 成摆设。**v0.7 分层原则**：重放型卡的**卡面概率是基线**（降龙十八掌 p=40%，裸卡无长尾），**套装/词条负责把 p 推入长尾区**（降龙套累计 +20% + 重放词条 ≤ +10% → p70%）——"卡面给基线、装备给放大"，p<50% 的"无长尾"由缺陷变成设计；装备侧封顶 +30%，使长尾是"堆出来的确定成果"。
4. 重放**不算新行动、不算新受击事件**——不触发任何其他武学，不与触发链耦合（只受本卡 C 封顶，与全局 8 层链无关）。
5. 重放索敌为卡面字段：**锁定**（全部重放打首次目标）或 **独立**（每次重放重新按目标规则索敌）。
6. 重放的数值计价：按期望命中 E 折算进预算口径（同放卡预算 0.35×普攻DPS 指期望贡献，含 E）。

**参数修正规则（v0.3 新增，装备套装与部分武学词条的修改对象）**：
1. 可修正的武学参数：`当前计数+N` / `需求次数−N`（下限1）/ `触发概率+x%`（上限95%）/ `重放概率+x%`（上限90%，防期望发散）/ `重放上限+N`（上限25）。
2. 同名参数多来源**加算后统一 clamp**。rationale：乘法修正会让"减需求次数"指数失控（需求 8→4→2→1 三步无敌），加算+下限保证每刀都疼但砍不死。
3. 生效时机：装备套装的修正在**战斗初始化**（开战事件）应用，整场生效；武学动态改计数（如"受击时使随机武学计数+1"）即时生效。
4. `当前计数+N` 语义：直接推进触发计数器，可因此立即触发（rationale：这是"蓄能"手感的来源，开局加速第一发）。
5. 参数修正**不开新乘区**——它改的是触发频率与链条长度，最终仍走既有伤害公式。这是与已砍羁绊系统的分界线：套装/词条做"build 工具"，不做"凑数乘区"。

## 10. 恒等式与不变量（改数值前先查这里）

1. `修为产出增长率 a ≈ 敌方HP增长率 a`（推层收益同步）
2. `消费增长率 d > a`（制造卡关心跳）
3. `道行增长 = 层数^0.5`（转世收益亚线性）
4. `乘区内加算、乘区间乘算`（膨胀可控）
5. `敌方 a > b`（卡关形态是打不动，不是被秒）
6. **标准轴 HP:ATK —— 基准 16.7:1 / 成长 20:1**（v4.4：基准 **1000:60**、成长 100:5）。rationale：HP 是"能站多久"的预算、ATK 是"多快打穿"的预算，二者之比直接决定 TTK 手感。**v5.8（2026-10-16）起三只全局 Scale 全部归 1、不再有隐藏乘数 —— 基准比就是有效比**（历史沿革见下方修订记录）。**2026-10-15 修订记录**：① 初版为基准 20:1（1000:50，成长 100:5，r 同为 0.10）；② M0 第一刀把 `AtkScale` 提到 2.2 却未同步血预算 → 有效比跌至 11.8:1，出现"脆皮两轮即倒"，把 `HpScale` 提到 **1.7** 拉回 **20.1:1**；③ **v4.4 ATK 基准 50 → 60**（用户口径"攻击60"），基准比降到 **16.7:1**，有效刻度（×HpScale 1.7 / ×AtkScale 2.2）随之由 15.5:1 降到 **12.9:1** —— **已接近早期出问题的 11.8:1，需实机复核**（当前探针 TTK 仍 38~44s，未见脆皮速倒）；④ **v4 起成长按属性独立随机、直接加算**（§11），个体侠客的侧重比会随等级漂移——**本不变量只约束"标准轴"，不再约束个体**；⑤ **v5.8（2026-10-16）三只全局 Scale 全部归 1**（用户口径："确保战斗时数值是多少就是多少，不要突然搞个谁都不知道的系数"）—— `HpScale 1.7` / `AtkScale 2.2` 的历史拐杖拆除，DEF 的 `0.25` 换算**折进 HeroConfig / EnemyConfig 两张内容表**（表值 4.7~10.6）。探针纯普攻镜像 **L1 48.0s / L20 52.7s / L40 54.0s，0% 超时**，未见脆皮速倒。

任何后续设计破坏这六条中的一条，先回本文档改公式并写明理由，再动配置表。（第 6 条按上述修订理解：约束的是标准轴而非个体。）

## 11. 侠客等级成长（1~40 级，2026-10-15 v4.4：直接加算 + 速度占模 + 事后归类）

**纯加算成长**：`属性(L) = 基础 + 每级成长 × (L−1)`。每级成长是**绝对值**——配置表上一眼能看出每级加多少血/攻/防，不再用"百分比偏差 × 标准增量"的间接表达。三条口径（用户定）：
1. **标准轴明确**：HP **1000**（+100/级）／ ATK **60**（+5/级）／ DEF **30**（+2/级）。**DEF 不乘定位系数**（v4.3），只有 HP/ATK 有。
2. **三项成长都不为 0**——HP / ATK / DEF **各自独立随机**（v3"允许某项完全不成长"已取消）。
3. 曲线类型仍是**先随机生成、再按形状归类**的结果，**不做满级收敛**；生成期加入**速度占模**。

```
Base(属性)   = 标准基准   × 定位系数 k × 基础随机 b × 速度占模 occ      ← HP/ATK 有 k；DEF 无 k（v4.3）
Growth(属性) = 标准每级增量 × 定位系数 k × 成长随机 g × 速度占模 occ     ← 直接加算（同上，DEF 无 k）
属性(L)      = Base + Growth × (L − 1)

标准基准： HP 1000 / ATK 60 / DEF 30    标准每级增量： HP +100 / ATK +5 / DEF +2
b ∈ [0.60, 1.40]         基础随机 ±40%（HP/ATK/DEF 三项共用同一个 b；决定 L1 强弱）
g ∈ [0.80, 1.20]         成长随机 ±20%（三属性**各自独立**，均非 0；决定涨幅强弱）
occ = clamp(1 − 0.6×(SPD−50)/50, 0.75, 1.25)   速度占模（SPD 50 = 不占模；越快属性越低）
SPD 不随等级成长（来源留给装备/境界）
```

**与 v3 的关键差别**：① 成长从"百分比偏差"改为**每级增量绝对值**（配置表即所见）；② **取消"某项完全不成长"**（三项均非 0）；③ 新增**速度占模**；④ **v4.1~v4.4 调 DEF / ATK**：DEF 基础 60→50→**30**、每级 0.6→**2**、并**去掉 DEF 的定位系数**（全池 19~42）；**ATK 基准 50 → 60**（标准单次伤害 110 → **60**，2026-10-16 三只 Scale 归 1 后；HP:ATK 20:1 → 16.7:1；内功 Kd 由用户定为 **100**）。三属性独立保留 → **侧重比随等级漂移**仍是刻意的（"只堆血"或"只堆攻"的极端成长型可由 k 与 g 的组合自然浮现）。

**三条性质**：

1. **侧重比按设计漂移**（v3 起保留）：HP/ATK 的 k 与三属性的 g 各自独立，HP:ATK 随等级变化。**DEF 不再有定位侧重**（v4.3 去掉 kD）——它只吃 b 与 occ，全池 DEF 差异只剩随机，不再有"坦更厚"的结构性差异。
2. **DEF 是"前中期偏弱、后期回升"的属性**（v4.4）：DEF 每级 **+2**（v4.3 是 +1.2）→ 满级 **×3.66**（HP ×4.9 / ATK ×4.25）。@60 档减伤 **7.9%~17.7%（L1）**，L40（单次 255 档）**8.3%~12.1%** —— 后期反而更薄（伤害涨得比 DEF 快）。DEF 的**前中期存在感比 v4.x 明显**（L1 减 8%~18%），**卡关的主要表达仍靠 HP 曲线与 §10 第 5 条**。
3. **速度占模把"高频率"折进属性**：occ 只作用于生成期、**不入任何字段**——引擎永远只读三列绝对值（`HeroGrowth` 纯加算展开）。"速度越快属性越低"是配置期的设计约束，不是运行期公式。

| 侠客 | SPD | occ | 效果 |
|---|---|---|---|
| 石敢当 | 40 | 1.12 | 最慢 → 属性 +12% |
| 柳如烟 | 60 | 0.88 | 最快 → 属性 −12% |
