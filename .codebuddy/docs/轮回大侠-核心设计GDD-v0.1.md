## 0. Fun Hypothesis 与设计支柱

**Fun Hypothesis**：这游戏好玩的核心是 **数字滚雪球的膨胀感**——伤害从 10 滚到 10 亿，而"配阵容、搭武学"是滚大雪球的手段：凑乘区、开乘区、拉高乘区效率。

**Design Pillars（不可妥协的玩家体验标准）**：

1. **膨胀为王**：数值服务膨胀，平衡是次要的；任何系统加入必须回答"它让数变大了多少"。
2. **构筑即乘区收集**：搭配的乐趣 = 开新乘区 / 拉乘区效率；不做机制博弈式平衡（无羁绊系统）。
3. **离线不惩罚**：玩家不在场时游戏继续给收益，但绝不在玩家不在场时惩罚玩家。
4. **转世是宿命不是按钮**：大劫定时上门，胜负由指数曲线自然决定，不做"第 N 次必输"剧本。
5. **武侠皮、江湖词**：全部系统命名走江湖/武侠术语，规避科幻/西幻词汇。

## 1. 核心循环（三层钩子）

| 层级               | 时长      | 循环内容                                                 |
| ---------------- | ------- | ---------------------------------------------------- |
| Moment-to-moment | 0~30s   | ATB 自动战斗演出 → 武学触发 → 掉落/修为进账                          |
| Session loop     | 5~30min | 上线 → 收离线收益 → 客栈看资质/调构筑 → 推层 → 卡关 → 回去调构筑/强化          |
| Long-term        | 小时~天    | 大劫倒计时 → 备战 → Boss 战 → 转世 → 道行点天赋树 → 以更高效率重爬 → 推过前世的坎 |

**在线与离线的关系**：战斗全自动，玩家的决策全部前置（战前构筑）与场外（养成、天赋、招募）。在线时玩家做"配队、搭武学、收菜、看演出"，不依赖实时操作。

## 2. ATB 战斗系统

### 2.1 基础结构

- **我方 4 个出战位**（1~4 号位），敌方按层数生成波次。
- **实时速度条**：每个单位有速度值，条满即行动；行动顺序完全由速度条驱动。
- **单场战斗目标时长 10~30 秒** [PLACEHOLDER：假设推图节奏为每分钟 2~~4 层；若实测玩家观看疲劳提前，压缩至 5~~15 秒]。大劫 Boss 战放宽至 1~2 分钟给演出。

### 2.2 概率仇恨（索敌模型）

- **普攻索敌 = 按受击权重随机抽取**。
- 权重系数 [PLACEHOLDER · 验证路径：用 Monte Carlo 模拟 1 号位坦度收益，目标 1 号位承担 45%~60% 普攻]：
  - 1 号位：**3.0**，并附带血量加成（定位：主坦位）
  - 2~4 号位：**1.0**
- 嘲讽/隐身类武学可临时修改权重（武学效果维度之一）。
- **技能（武学）不随机**：每张武学卡面写明目标规则（随机单体 / 最前排 / 血最少 / 全体 等）。
- 设计原则：**普攻赌概率，技能讲规则**——站位的价值由权重体现，构筑的确定性由技能保证。

### 2.3 触发式武学系统（核心机制，无冷却）

**武学 = 事件源 × 触发条件 × 效果**。彻底消灭冷却条。

| 维度   | 取值                               | 说明             |
| ---- | -------------------------------- | -------------- |
| 事件源  | 行动 / 受击 / 血量变化（可扩展：击杀、闪避、队友死亡）   | 决定武学"什么时候有机会放" |
| 触发条件 | 次数型（第 N 次）/ 概率型（x%）/ 状态型（血量<30%） | 次数型给确定性，概率型给方差 |
| 效果   | 伤害 / 治疗 / 护盾 / 修改权重 / 召唤 / 增益减益  | 卡面写明目标规则与数值    |

组合示例："受击 2 次释放"、"受击时 30% 释放"、"血量首次低于 30% 释放"。

**普攻规则（已钉死）**：

- 每次行动默认放普攻。
- 行动类武学触发时**默认与普攻同放**（普攻+武学都打）。
- 标注"**不能普攻**"词条的武学触发时**替换**该次行动的普攻——作为设计词条，占用行动的武学数值可以给得更狠，构成"普攻流 vs 技能流"路线分叉。
- 受击/血量类武学是额外触发，永不占用行动。

**速度属性双吃**：行动多 = 普攻多 = 行动类武学触发多 → 速度是滚雪球核心乘区之一。

### 2.4 召唤物

- 不占 4 个出战位，由召唤类武学产生。
- 独立血量、限时存在，固定速度、只会普攻（简化模型，不占用玩家构筑心智）。
- 加入受击权重池——召唤物是临时肉盾。

## 3. 大劫转世系统（Prestige 循环）

### 3.1 规则（已钉死）

- 游戏进行到一定时间，**大劫上门**（武侠皮：仇家杀到 / 天劫），倒计时全 UI 可见。
- **Boss 强度纯指数增长**：`Boss强度 = 基础值 × k^n`（n = 已转世次数，k [PLACEHOLDER · 初始假设 k=1.8；验证路径：模拟玩家 DPS 成长曲线 vs Boss 曲线，目标前 2~3 次大劫可胜，之后自然败北]）。
- **不设剧本必输**：打得过就继续此生（拿 bonus 道行、下次大劫更强），打不过就转世。数学上必输，设计上不锁死——构筑够妖理论上多撑几轮。
- **输赢都拿道行**：道行按此生成就折算（见 4.2），胜利只是 bonus。被迫转世永远不亏。
- **离线不空转**：玩家离线期间倒计时到期，Boss"等你回来才出手"。

### 3.2 道行折算

- `道行 = (此生最高通关层数)^0.5 × 系数` [PLACEHOLDER · 亚线性是保命公式：保证转世收益递减，逼玩家"转世→更快回到原进度→再推进一步→再转世"]。
- 首次大劫设计在 **2~4 小时**到达 [PLACEHOLDER · 太短没有仪式感，太长玩家流失前没体验到核心循环；验证路径：首轮 playtest 记录到达时间与留存]。

### 3.3 转世账本（心理账本一目了然）

| 转世后          | 内容                      |
| ------------ | ----------------------- |
| **保留（跟你走）**  | 侠客池（已解锁）、图鉴、根骨乘区、天赋树、道行 |
| **归零（此生重来）** | 侠客等级、武学强化、装备、境界、修为      |

## 4. 经济系统（Sources & Sinks）

### 4.1 双货币

| 货币     | 定位    | Sources                     | Sinks                    |
| ------ | ----- | --------------------------- | ------------------------ |
| **修为（= 经验）** | 此生成长 | 打怪掉落（随层数指数增长）、离线收益、大劫 bonus | **侠客升级**（攒满自动消耗，玩家零操作） |
| **银两** | 此生主货币 | 打怪掉落（随层数指数增长）、离线收益、大劫 bonus | 客栈招募侠客、武学商店、装备强化/洗炼、突破境界 |
| **道行** | 永久货币  | 转世折算（唯一来源）                  | 天赋树（唯一出口）                |

### 4.2 五乘区（全部乘算进伤害公式）

| 乘区     | 类型   | 转世 | 说明                                            |
| ------ | ---- | -- | --------------------------------------------- |
| ① 武学乘区 | 构筑核心 | 归零 | 武学本身是乘算项；无羁绊系统，深度来自单体机制联动（流血×暴击、护盾×反伤）        |
| ② 境界乘区 | 此生纵向 | 归零 | 炼气→筑基→金丹→元婴…每境一个大乘数 + 解锁武学槽 [境界表 PLACEHOLDER] |
| ③ 装备乘区 | 掉落驱动 | 归零 | 推图掉落，词条随机，修为洗炼                                |
| ④ 根骨乘区 | 永久   | 保留 | 天赋树中的数值节点                                     |
| ⑤ 图鉴乘区 | 永久收集 | 保留 | 收集过的侠客/武学提供小额永久加成，长线钩子                        |

**通胀检查**：**银两**的最大 sink 是客栈招募与装备洗炼（价格几何上涨 [PLACEHOLDER]）；道行严格亚线性产出；**修为（=经验）不进通胀账** —— 它被自动升级即时消耗、不留存。任何新系统加入必须在此表登记 source/sink。

### 4.3 离线收益 [假设 · 待确认]

- 按最近 N 场战斗的推层效率模拟折算，累积上限 8 小时 [PLACEHOLDER]。
- 离线期间大劫倒计时暂停（见 3.1）。

## 5. 侠客系统

### 5.1 解锁制（无抽卡）

侠客通过**里程碑解锁**：打到特定 Boss、成就、轮回天赋树节点。解锁即永久进侠客池与图鉴。给玩家明确的长期目标树。

### 5.2 客栈与资质

- **每世客栈刷新侠客资质**——已解锁的侠客在客栈中随机生成当世资质（属性成长倾向 / 词条维度 [PLACEHOLDER · 资质随机范围待逐条对齐]）。
- 玩家用**修为招募**入队（价格扁平，每世刷新重招——修为的常驻 sink）。
- 模型：**侠客 = 永久解锁的英雄池，资质 = 每世随机的手气**——rogue-lite 的"这把命"混进滚雪球。

### 5.3 侠客结构

- 侠客是**容器**：提供定位（坦 / 输出 / 辅助 / 召唤）、基础属性、相性标签（剑 / 刀 / 毒 / 医…）。
- 每个侠客 **3 个武学槽**，武学从通用池自由装配；同标签武学装到同相性侠客有加成（无相性则无加成，不产生羁绊计数）。
- 构筑空间账 [假设]：20 侠客 × 40 武学 × 3 槽 × 4 人 → 组合空间足够滚到后期。

## 6. 道行天赋树

- 道行**唯一出口**，节点三类混合：
  1. **数值节点**：根骨乘区（全局伤害/血量/速度加成）；
  2. **机制节点**：解锁新功能（第 5 个客栈栏位、武学槽+1、离线上限提升…）；
  3. **侠客节点**：解锁特定侠客。
- 树形结构制造取舍：道行永远不够点满，选择即构筑（局外 build）。
- [PLACEHOLDER：首版天赋树规模 30~50 节点；验证路径：playtest 观察玩家是否出现"点哪条都差不点"的错觉——若有，说明节点差异化不足]

## 10. 已定决策清单（拷问结论速查）

1. 全自动 ATB，构筑前置；在线乐趣 = 战前配队搭武学（自走棋式）。
2. 4 人位 + 召唤物；普攻按受击权重随机，1 号位高权重+血量加成。
3. 武学无冷却：事件源 × 次数/概率 × 效果；行动类默认与普攻同放，"不能普攻"词条替换。
4. 滚雪球为主，构筑 = 乘区收集；无羁绊系统。
5. 大劫转世：Boss 纯指数增长，胜负自然发生，输赢都拿道行，离线不空转。
6. 双货币（修为/道行）+ 五乘区（武学/境界/装备/根骨/图鉴）。
7. 侠客解锁制（Boss/成就/天赋树）+ 每世客栈刷资质 + 修为招募。
8. 道行全走天赋树（数值/机制/侠客三类节点）。
9. 单机买断，Steam + TapTap，仅云存档联网。
10. 游戏定名《轮回大侠》——点题大劫转世循环。
11. 武学重放机制：释放后按重放概率重复判定，上限封顶；重放不算新事件、不触发其他武学；锁定/独立两种索敌；**全局基线 p=1%/上限2**，卡面显式字段替代基线，套装/词条修正叠加（p≤90%，C≤25）。
12. 参数修正系统：武学/装备可修正 当前计数/需求次数/触发概率/重放概率/重放上限 五字段，加算+clamp；只改参数不开新乘区（与已砍羁绊的分界线）。
13. 武学启用经典武侠原名（用户拍板）：金庸/古龙/梁羽生/诛仙出处照用，命名风险三层管理 + 变体名对照表备上架切换；宣传素材不与原作者/作品做关联表述。
14. **卡面给基线、装备给放大**（v0.7）：重放型武学卡面概率压在"能看出重放、打不出奇迹"档（降龙十八掌 p 70%→40%，裸卡 E≈1.67 无长尾），长尾奇迹（十八连）由装备解锁——**卡面 40% + 降龙套 20% + 重放词条 ≤10% = 上限 70%**。rationale：卡面给满则装备白给；装备侧封顶 +30%，保证长尾是"堆出来的确定成果"，随机词条不喧宾夺主。
15. **属性模型修订（2026-10-15）**：①**保留防御**（推翻早期"不做防御"）——DEF 参与减伤；②伤害分**三种减免口径**：**外功 = 基础−DEF（硬减）**、**内功 = 比例化解 ×Kd/(Kd+DEF)（收益递减）**、**真伤 = 无视减伤（稀缺）**——外功靠倍率堆量、内功靠频率摊薄，真伤用于破局；③**受击权重改 10 基准**（原 1.0 基准 ×10，纯单位换算、平衡不变，1 号位 30、其他 10、下限 1）。公式见数值框架 §1/§2/§7。
16. **成长随机化 + 防御下探（2026-10-15）**：①**标准轴定死**——HP **1000**（+100/级）／ ATK **50**（+5/级；**v4.4 已改为 60，见决策 19**）／ DEF **60**（+0.6/级，由 100 下调；**v4.2 已改为 30 / +1.2，见决策 18**）；②**成长偏差按属性拆开**：HP / ATK / DEF **各自独立随机**，取值 `{0} ∪ [80,120]`，**0 = 该属性完全不成长**（刻意允许"只长血不长攻""防御永不长"这类极端成长型）；③基础偏差仍 **±40%** 三项共用；④**曲线类型（早熟/均衡/晚成/技巧）是先随机生成、再按形状归类的【结果】**，不是设计输入；⑤**不做满级收敛**（个体强度差保留为方差）。代价：三属性独立 → 侧重比 HP:ATK 随等级漂移（v2 的"侧重恒定"性质撤销）；**Kd 由 400 修正为 110**（原值远大于单次伤害量级，使内功公式形同失效）。模型见数值框架 §11，公式见 §2。
17. **成长改直接加算 + 速度占模（2026-10-15，v4）**：①成长字段改为**每级增量绝对值**（基准 HP +100 / ATK +5 / DEF +1.2 每级；DEF 数值与成长经 v4.1/v4.2 两轮调整，见决策 18），`属性(L) = Base + Growth × (L−1)`——**配置表即所见**，不再用"百分比偏差 × 标准增量"的间接表达；②**三项成长均不为 0**（取消 v3"允许某项完全不成长"——它曾把老乞丐/剑魔的攻随机判成不成长、与世界观的输出定位直接冲突）；③新增**速度占模** `occ = clamp(1 − 0.6×(SPD−50)/50, 0.75, 1.25)`，速度越快属性越低（把"高行动频率"折进属性）；④曲线类型（早熟/均衡/晚成/技巧）仍是**先随机生成、再按 `E=√(g_hp×g_atk)` 形状归类的【结果】**。生成器随机跑 10 个种子、取类型分布最均衡的一次（**seed=7**，四类 5/5/6/4）。效果：满级跨度由 v3 的 **ATK 5.5× / HP 3.7× 收敛到 ATK 2.2× / HP 1.9×**，"满级属性差不多、侧重不同"基本达成。模型见数值框架 §11。

27. **飞剑改成"命中计数体" + 一次召唤多只（2026-10-16，v5.6）**：口径"御剑术是召唤2飞剑(不是上限),飞剑血量固定为2,每次受击-1"。① **`SummonConfig` 新增 `FixedHp` / `DmgPerHit`**：`FixedHp > 0` 时气血用**固定值**（不乘召唤者、**不吃全局 HpScale** —— 是"层数"不是血池）；`DmgPerHit > 0` 时**无视伤害量**，一次命中只扣该值。**飞剑 = 2 层计数体**（`HpRatio` 归零、`FixedHp=2`、`DmgPerHit=1`）。这是**换了一套生存模型**：飞剑**免疫一发大伤害秒杀**（敌方 ATK 132 还是 1,000,000 都只掉 1 层），代价是被**高频多次命中**（AoE / 连击 / 多段）克制得极狠 —— **脆皮死于伤害量，飞剑死于命中次数**。② **`SkillConfig` 新增 `SummonCount`**（每次触发召唤几只，与 `SummonMax` 同时上限是两件事）：**御剑术 = 2**（一次召 2 把）、**SummonMax 2 → 0**（"2"不是上限，跟随剑类档位）。**实测（探针）**：召唤者 HP 200/1000/20000 → 飞剑 HP 恒为 **2**；敌人 ATK 1 / 132 / 1e6 → 全部**2 次命中必死**；御剑术单卡首次触发后在场 **2 把**、峰值 2 把，万剑归宗 1 把，两卡齐上峰值 **3 把**。
28. **全队召唤上限 4 → 8 + 同类召唤物堆叠显示（2026-10-16，v5.7）**：口径"全队召唤上限提高,同一召唤物显示上可堆叠"。① **`BattleConfig.SummonCap` 4 → 8** —— 理由：4 侠客 × 2 = 8，让"每人带一张以上召唤卡"的召唤流真能同时铺开；同时它仍是**外层闸**，单卡上限由类型档位（1/2/3/2）与武学覆盖管住（那个"先到先得独占全席"的病在 v5.3/v5.4 已修）。② **表现层堆叠卡** —— 把**同阵营 + 同名字**的召唤物合并成一张卡，显示 `名字 ×N`、**聚合血条**（Σ当前 / Σ上限）、**最快到期的剩余时间**。这两条是**配套**的：上限提到 8 后，一单位一卡的旧布局会把战场塞爆并超出 720p 高度。可行性来自结构事实：**召唤类型只有 4 种** → **每侧最多 4 张堆叠卡**（放在中路两侧，不占侠客卡列），4 × 62px 稳定放得下。**实测（探针）**：`sub+sub` 峰值 3+3 = **6**（v5.6 时被全队 4 兜住）、`tank+dps+sub` → **6**、类型上限置 0 → **8**、**六卡齐上（类型上限合计 12）→ 8**；真实推图 60 场残留尸体 0。

29. **Scale 全部归 1 + 系数总账表 + 治疗/护盾口径修复（2026-10-16，v5.8）**：① **三只全局 Scale 归 1**（用户口径："atkscale,hpscale,defscale都改回1" + "确保战斗时数值是多少就是多少，不要突然搞个谁都不知道的系数"）—— 引擎侧不再有任何隐藏乘数，**表里的值 = 战斗里的值**，玩家可用卡面数字直接算伤害；DEF 的 `0.25` 刻度换算**改在构建期完成**（折进 HeroConfig / EnemyConfig 两张内容表，表值 4.7~10.6）。② **新增第 5 张内容表 `TuningConfig`（系数总账）** —— 把散落在代码里的 **61 项系数**（49 运行时 + 12 仅登记）收成一张行式 key-value 表，带 **`Source` 审计列**（用户指定 21 / 用户口径 7 / 文档规定 5 / **自拟 28**）与 `Note`；`Tuning.cs` 启动时反射注入各常量类，并做**表 ↔ 代码双向校验**（任一侧漏登记即报错）。③ **修"治疗/护盾漏乘攻击"** —— `BattleSkill.Mult` 一字段承载两种语义（倍数 / 绝对量），引擎**只有伤害**乘了攻击，导致所有"×攻击"型治疗/护盾退化成 1.22 的绝对值（界面表现为 **"全队护盾 1"**）。新增 `MultOnAtk` 标记基准、引擎统一走 `AmountOf` 入口。**该修复让含武学镜像超时率从 87.3% 降到 35.3%**，并推翻了一个此前的错误归因：**僵局主因不是"护盾/治疗太强"，而是"输出位在 1 号位承伤机制下先死、战场退化成双坦互掐"**（推导见数值框架 §2.1）。④ 治疗/护盾 7 张卡累计下调 **−19%**（削续命）+ 敌方小怪攻击 **+10%**（抬承伤）；掉落底数维持 1.16（用户："已经随层级涨了,那就不改"）。

30. **M2.3 客栈：资质刷新 + 招募 + 编队（2026-10-16）**：① **每世自动刷 4 栏**（`InnConfig.InnSlots`），每栏 = 一名侠客 × 一份**资质**；栏内可刷新，已招侠客**当世锁定、不可退换**（rogue-lite 的"认命"感）。② **资质三件套**：**★1~★5**（权重 50/30/12/6/2%）→ **全属性乘数** `1 + (星−1)×0.15`（★5 = ×1.6）；**三维成长率** ∈ [−20%, +30%]（均值 5%，**单维为负约 40%** —— 刻意保留"瘸腿天才"）；**词条 0~2 个**（40/45/15%）取自内容表 `QualityConfig`。③ **成本**：刷新**首免**、之后 `20 × 2^n` 银两；招募 `30 × (1 + (星−1)×1.0)` 银两（★5 = 5×），**价格扁平、不随次数涨**（区别于刷新的递增）。④ **资源口径修正**：原文档写"招募用**修为**"，但修为 = 经验、被自动升级即时吃掉（决策 20 的双资源口径），故**改用银两**；《侠客与资质》§二的三处已同步改口径。⑤ **落地**：`Scripts/Game/Inn/`（`Inn` / `HeroQuality` / `InnConfig`）+ 第 6 张内容表 `QualityConfig`；`HeroBuilder` 新增资质参数并**在技能装配前应用**（"气血上限%"类技能须按新气血上限折算）。⑥ **[假设 · 待确认]** 开局 4 名是**无资质基准版**（★1/成长 0/无词条），客栈刷出的才是"带手气的版本" → "招募同名侠客" = 用资质版替换基准版，机制自洽且开局强度稳定。⑦ **[已定，2026-10-16]** ★ **不作用于 SPD**（口径"高星行动频率去掉"）—— 只乘气血 / 攻击。理由：DPS ≈ 攻击 × 频率，若 ★ 同时乘两者就是**二次放大（★5 ≈ ×2.6）**，不该让一个 2% 概率的乘数承担这种杠杆。落地：`HeroQuality.ApplyTo` 的 SPD 行改为只吃成长率 `SpdPct`。⑧ 探针实测：星级/词条/成长率分布**全部落在期望内**（见《侠客与资质》§二 M2.3 落地记录）。

31. **资质词条八类全实装 + 客栈界面（2026-10-16）**：① 词条效果词从"4 类实装 / 4 类待实装"变为**八类全部实装** —— 原待实装的 `MulPct`（武学倍率）/ `HealPct`（治疗量）/ `SummonHpPct`（召唤物气血）/ `DmgTakenPct`（受击伤害）全部接上；`QualityConfig` 6 条词条 Status 全为"已实装"。② **实现分两条路径**（判据是"这个效果结算时问谁要数"）：**装配期折进 `BattleSkill.Mult`** —— `MulPct` / `HealPct` 由 `HeroBuilder.ApplyQualityToSkill` 在**装配技能时**乘一次。因为引擎的伤害与治疗都走同一个 `AmountOf(u,s)` 入口，"倍数"与"绝对量"两种语义都能被正确放大，**不需要动引擎**。**引擎钩子字段** —— `SummonHpPct` → `BattleUnit.SummonHpMul`（`SpawnSummon` 里乘，**只作用于比例血型**，计数体飞剑的"2 层"是机制不是血池）；`DmgTakenPct` → `BattleUnit.DmgTakenMul`（`DealDamage` 里乘在承伤链最前）。两者都进了 `Clone()`（装配期属性，跨波延续要带上）。③ `MulPct` 的"限定范围"**复用既有的 `SkillConfig.Category`**（相性/流派枚举：剑/刀/拳/掌/腿/鞭/暗器/轻功/医/毒/奇门/禅/兽，66 张武学早已各自标好），`QualityConfig` 新增一列 `Category` 做匹配，**0 = 不限相性**。"剑心通明"= `MulPct 15 + Category 剑`。**没有新增相性系统** —— 只是把已有的一列接上，真正的相性玩法（克制关系等）仍属 M2.4。④ **客栈界面** `InnView.cs`（表现层，纯程序化搭建）：4 栏位卡 + 刷新/招募按钮 + 已招侠客的编队开关；`BattlePanel` 左上角「客栈 ⌂」进入，**打开即暂停战斗**，返回时恢复（战斗进行中→继续本场；结算等待中→继续进层）。⑤ **探针实测**：星级★5 → HP ×1.600 / ATK ×1.600 / **SPD ×1.000**；剑心通明 → 剑系卡 ×1.150（非剑系不变）；妙手回春 → 治疗卡 ×1.250；百兽之王 → `SummonHpMul` 1.30、端到端召唤物峰值气血 **306 → 397（×1.300）**；嗜战如命 → ATK ×1.150 + `DmgTakenMul` 1.05。编译 **0 警告 0 错误**。⑥ ⚠️ **客栈界面仅编译通过，待实机验收**（AI 环境起不了 Godot）。
