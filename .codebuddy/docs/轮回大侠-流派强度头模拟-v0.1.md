# 《轮回大侠》流派强度头模拟 v0.1

> 2026-10-24。无头模拟器工程：`D:\Godot\RebirthProbe`（`dotnet run -- 200`）。
> 目的：找出 300 张武学里哪些流派实际废、哪些超模，并把能量化的部分先调平。

## 一、结论先行

| 结论 | 证据 |
|---|---|
| **DoT 的"每层 1 点"数值太小，但解法是抬层数不是抬点数** | 1 点 vs 普攻 60 点 = 1/60。层数放大 6 倍后毒爆 53%→**84%**、火 49.5%→**75%**，点数一个字没动 |
| **召唤的"98% 超模"是模拟器 bug** | 探针漏了 `HeroBuilder` 的"每张召唤卡 −15% 生命"，补上后立刻 98.5% → **74%**；再加"受击权重 +2/张"后 **65.5%** |
| **盾攻/受击/增减益 结构性偏弱** | 40~51%，且三个都不直接产生伤害 |
| **固定点数 DoT 后期必然崩** | 第 12 层火 8.5%、治疗 7%，直伤 58.5%（点数不随层成长，层数放大只补了 6 倍量级） |

## 二、方法（以及它测不到什么）

- **控制变量**：4 人队全部用标准轴 L1（HP 1000 / ATK 60 / DEF 7.5 / SPD 55），
  等级 1、无装备、无资质、无词条 —— **只有卡组不同**。
- **两套配卡口径**：A 纯流派（4 槽全本流派，看机制天花板）；**B 混搭（2 本流派 + 2 直伤，看机制效率）**。
  ⚠️ 结论以 **B 为准**：A 口径对"有硬上限的机制"不公平（纯召唤队 4 槽全召唤，超过上限的卡全废，
  结果反而显示召唤不强）。
- **敌人**：`EnemyFactory.BuildWave` 的真实波次，第 9/10/11/12 层普通波（4 小怪）。
- **场次**：每档 200 场，固定种子组。
- **测不到**：玩家随层的等级/装备成长（所以只测 9~12 层）；PvP；长线资源循环。

## 五、没解决的三件事（需要拍板）

### 1. 召唤：已解决 —— 但先说一个更重要的发现

**先说模拟器自己的 bug**：探针的 `BuildPlayer` 只实现了技能装配，**漏了 `HeroBuilder` 里的
"每携带 1 个召唤武学 −15% 最大生命"这条代价**。所以前面所有数据里召唤流的 98.5% 是**假高**，
它一直在无代价状态下被测试。

补上这条代价之后（`summonerW = 0`）：**召唤立刻从 98.5% 掉到 74%**，与直伤 77% 齐平。
也就是说"削 Ttl / AtkRatio / HpRatio / SummonCap 全都无感"这个结论本身是被 bug 污染的 ——
召唤流本来就不超标，是我给它的血条多了 30%。

**用户的新口径**（"携带召唤技能的侠客受击概率提高"）已实装为第二条代价：
每张召唤武学 **受击权重 +2**（`Tuning.SummonerWeightPerSkill`）。

权重斜率实测很陡（200 场，B 口径第 11 层）：

| 每卡权重 | 0 | **2** | 3 | 5 | 10 |
|---|---|---|---|---|---|
| 召唤流胜率 | 74.0% | **65.5%** | 57.5% | 53.0% | 36.0% |

定 **2**：从"和直伤齐平"压到"明确低于直伤一档"。再大就会让召唤流废掉 ——
它还背着 −30% 生命（两张召唤卡），而权重抬到 30 时一个人要扛全队一半的火力。

**教训（写进规范）**：探针必须和 `HeroBuilder` **逐行对齐**装配逻辑，
少一条代价就能把结论带偏 24 个百分点。

### 2. 固定点数 DoT 后期必然贬值

第 12 层：毒爆 22.5%、火 8.5%，直伤 58.5%。原因很硬：点数固定，敌人 HP 每层 ×1.16，
而直伤卡按 ATK 缩放。**这是"不按百分比"的结构性代价，不是数值没调够。**

三个选项：
- **A** 接受它做"前期/低层流派"（设计定位，不再调）
- **B** 每层每跳改成**施法者攻击 ×X%**（随成长，仍然"每层一个数"）
- **C** 点数不变，但"每次施加层数"随施法者等级放大（曲线补偿）

### 3. 盾攻 / 受击 / 增减益：三个不直接产生伤害的流派

- **盾攻 48%**：根因不是倍率（×2 无效），是**没有盾**——护盾卡每 4~6 次行动才给一次，
  且 `Act()` 开头先按保持率 0.5 衰减，按盾加伤卡经常在"盾只剩渣"的时候结算。
- **受击 39.5%**：反伤吃"累计受击伤害"，越能扛反伤越低，是负反馈；且反伤是内功，吃 DEF 化解。
  纯受击口径下还会把战斗拖满 120 秒（僵持）。
- **增减益 41%**：92 张卡里大部分是属性型被动（装配即生效、不进战斗），剩下的减益
  （W+ / SPD− / ATK− / 沉默）只增加生存，不加快击杀。

这些都是"设计要不要加转换环节"的问题，不是纯数值能救的：
- 盾攻：提高护盾卡的盾量（现在 4.5~26% 气血上限）
- 受击：反伤改"按自身攻击力保底"或改外功
- 增减益：加"减益层数 → 伤害"的转换卡

## 六、最终口径修正（2026-10-24 用户拍板）

> "dot,hot 每层每跳就是 1 点，觉得数值低可以提高叠层数的效率；不要改动规则"

所以 §四 里"把点数提到 6/2"的方案**作废**，改成**点数回 1 + 层数放大**：

| 项 | 改法 | 结果 |
|---|---|---|
| 毒每层每跳 | 6 → **1**（回滚） | — |
| 火每层每跳 | 2 → **1**（回滚） | — |
| 毒 / HoT 每次施加层数 | ×6 → **12 / 24 / 36 / 48 层** | 毒爆 75% → **84%** |
| 火每次施加层数 | ×2 → **6 / 12 / 18 / 24 层** | 火 75% → 75%（等价替换，验证正确） |
| `StacksOf` 护栏 | 20 → **60** | 允许 48 层通过 |
| 引爆毒层 `PoisonBurst` | 0.7 / 0.6 → **0.12 / 0.10** | 引爆伤害 = 攻击×倍率×层数，层数放大 6 倍必须同步 ÷6，否则一发 25×攻击 |
| 百淬 4 件 `DotStackUp` | 1 → **8** | "+1 层"在 48 层基数上只剩 2%，放大到 +8 |

**最终数据（B 混搭，200 场，第 11/12 层胜率）**

| 流派 | L11 | L12 |
|---|---|---|
| 毒爆 | 84.0% | 50.5% |
| 治疗 | 79.5% | 7.0% |
| 直伤（基准） | 77.0% | 58.5% |
| 火 | 75.0% | 8.5% |
| 斩杀 | 66.0% | 45.0% |
| **召唤**（补上两条代价后） | **65.5%** | 3.5% |
| 破绽 | 63.0% | 24.5% |
| 盾攻 | 48.0% | 5.0% |
| 增减益 | 41.0% | 2.0% |
| 受击 | 39.5% | 5.5% |

第 11 层的跨度从开测时的 41~98 收到 **39.5~84**，九个流派挤在 39.5~84 这 45 点里，
中间五个（火/斩杀/召唤/破绽/治疗）只差 16 点。
**仍然偏低的只有盾攻 / 增减益 / 受击三个不直接产生伤害的流派**，见 §五 的决策请求。

**已知副作用**：层数放大 6 倍后，"解毒 −5%、最少留 1 层"这条反制变弱了
（保底 1 层在 8 层时代占 12.5%，在 48 层时代只有 2%）。毒爆从 75% 涨到 84% 有一部分是它。
